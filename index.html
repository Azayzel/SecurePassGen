Words drawn from the EFF large list — 7,776 words, ~12.9 bits each. Separators and casing add no entropy and are not counted.

Most strength meters read a finished string and guess how hard it looks: they hunt for dictionary words, keyboard runs, and digit suffixes, then map their guess onto a 0–4 or 0–100 score. That guess depends on the meter's word lists and rules, so the same password scores differently in different tools, and a meter can be fooled by a pattern it never learned.

Pegasus reports the entropy of the process that made the secret. When you draw L characters uniformly from an alphabet of A, an attacker who knows your exact settings still faces L · log₂(A) bits of search. That figure is exact for a uniform generator, and it does not flatter or punish any particular output.

An offline attacker checks billions of candidates per second against a leaked hash. Each added bit doubles their work. Around 60 bits resists casual cracking, and 128 bits sits beyond any foreseeable budget, which is why the meter above marks it as the target.

How it works. Entropy comes from crypto.getRandomValues. Indices are drawn by rejection sampling, so there is no modulo bias. Class rules are met by redrawing whole candidates rather than injecting characters, which keeps the output uniform. Reported bits measure the generation process, not a heuristic score.
